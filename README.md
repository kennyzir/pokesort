# PokeSort

A static, no-login daily Pokémon grouping puzzle designed to put the playable board before marketing copy.

## Local preview

```powershell
npm run dev
```

## Production build

Set the real public origin so canonical links, Open Graph URLs, structured data, `robots.txt`, and `sitemap.xml` point to the deployed domain:

```powershell
$env:SITE_URL = "https://your-domain.com"
npm run release:gate
```

The production build includes Google Analytics 4 measurement ID `G-JEJ6WJ88P3`. To use a different web stream, set `PUBLIC_GA_MEASUREMENT_ID`; set it to an empty string to build without analytics:

```powershell
$env:PUBLIC_GA_MEASUREMENT_ID = "G-XXXXXXXXXX"
```

The held Pokelike Today route reuses that single tag and emits only the low-cardinality events disclosed on `/privacy/`. Inspect repo-local shadow freshness, consecutive verified dates, and failure-drill coverage without contacting GA4 or GSC:

```powershell
npm run generate:pokelike-drills -- --write
npm run monitor:pokelike-readiness
```

`generate:pokelike-drills` is deterministic and offline. Its default mode prints two clearly marked `simulated: true` records without writing; `--write` creates immutable evidence only under `data/pokelike/drills`. It never contacts Pokelike and never writes to `data/pokelike/shadow`. The acquisition-failure scenario uses a controlled offline error and the stale scenario advances a fixture clock. These records can satisfy only the two failure-drill checks: they never count as an official observation, a good date, or part of the seven-day run.

The monitor defaults to the `Asia/Shanghai` capture lane, requires the seven-date run to end on that lane’s current local date, and rejects latest evidence older than 26 hours. Override those policies explicitly when auditing another capture lane:

```powershell
npm run monitor:pokelike-readiness -- --timezone UTC --expected-local-date 2026-08-24 --max-age-hours 26
```

Only live records under `data/pokelike/shadow` whose manifests, two retained official samples, hashes, 720-permutation counters, and state transitions reconstruct successfully count toward the seven-day Gate. Duplicate dates count once. Failure drills are loaded separately from `data/pokelike/drills`; their simulation marker, scenario contract, fixture, clock/error trigger, and evidence hash must validate. Override either source explicitly with `--directory` or `--drill-directory`. The report deliberately marks observed GA4 events, GSC Query × Page data, and field performance as `UNVERIFIED` until separately authorized external access supplies evidence.

Deploy the generated `dist/` directory to Cloudflare Pages, Vercel, Netlify, or any static host. For Cloudflare Pages, use `npm run release:gate` as the build command, `dist` as the output directory, and add `SITE_URL` as an environment variable. That is the same fail-closed data/security/build Gate used by local release checks and all scheduled Daily jobs.

The build also emits a Pages Advanced Mode `_worker.js`. It permanently redirects `www` to apex, migrates legacy Infinite and generated-window date queries to clean routes, and forwards every other request to the static asset binding. Its date range is pinned to the exact routes generated by that build, so rebuild after UTC midnight when a fresh rolling Archive is required.

`.github/workflows/daily-archive-refresh.yml` defines three explicit jobs: prepare the private future buffer, publish only the newly elapsed immutable history entry, and monitor API/buffer/archive readiness. Every job runs the same `npm run release:gate` used by the Cloudflare build. External KV/API activation is held unless `POKESORT_DAILY_AUTOMATION_ENABLED=true`, the expected Cloudflare account matches, and the required encrypted secrets and isolated bindings exist. With the flag absent, the static Daily deployment remains unchanged. The independent Pokelike shadow workflow never publishes Today answers.

## Puzzle data

The versioned Pokémon snapshot covers National Pokédex species #1–1025. Production builds consume only the tracked, immutable elapsed-history subset in `data/puzzles/public-daily`; ignored future candidates are not a build dependency and never enter routes or the sitemap. Infinite uses a separately validated finite pool. Both systems require a complete one-partition solver proof and never fall back to the legacy three authored fixtures. Public Infinite category-family claims are emitted only from an R3 PASS capability report.

```powershell
npm run refresh:pokemon-data
npm run build:daily-calendar
npm run validate:daily-calendar
npm run build:infinite-pool
npm run validate:infinite-pool
```

The refresh command is the only ordinary puzzle command that accesses the network. Calendar and pool builders are deterministic and refuse to overwrite existing files with different bytes. Extending the Daily range after `2027-07-24` requires a reviewed, versioned calendar extension before that date.

## Validation

```powershell
npm install
npm test
```

The full test command runs static SEO/product checks and real browser interactions in an installed Google Chrome channel. Set `POKESORT_BROWSER_CHANNEL` to another Playwright-supported branded channel, or `POKESORT_CHROME_PATH` to an explicit executable, when Chrome is installed elsewhere. `npm run test:static` is available for environments that intentionally cannot launch a browser, but it is not the complete release Gate.
